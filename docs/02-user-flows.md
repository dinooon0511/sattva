# User flow — пути и состояния

Проектная схема, основанная на брифе. Все имена, цены и доступность в будущих экранах — демонстрационные до предоставления реальных данных.

## 1. Первый визит и быстрый результат

Telegram-пост / соцсеть / поиск → прямая страница или главная нужного направления → просмотр без регистрации → «Подобрать практику» → цель (расслабиться / двигаться / сосредоточиться) → доступное время → опыт → результаты с объяснением подбора → детали → бесплатный старт → завершение → «Как вы себя чувствуете?» (можно пропустить) → сохранить / выбрать следующую практику.

Ветви: пропустить подбор → каталог; нет совпадений → снять один фильтр; материал платный → видимая цена и описание доступа до оформления; авторизация требуется для сохранения, а не для знакомства. Не запрашивать медицинскую анкету как обязательный шаг.

## 2. Возвращение и медиатека

Вход → «Продолжить» → последнее место в аудио / видео / уроке → воспроизведение с паузой, перемоткой и транскриптом → завершить → сохранить результат по желанию. Альтернатива: каталог → медитация / подкаст / тренировка / вебинар → фильтры длительности и уровня → материал → воспроизведение.

Ветви: отсутствует сеть → объяснение и повтор; доступ закончился → условия продления; медиа недоступно → альтернативный материал и помощь. Восстановление прогресса не требует завершать весь материал заново.

## 3. Мастер и индивидуальная услуга

Каталог / рекомендация → фильтры → профиль мастера → подход, квалификация, услуги, стоимость, формат → услуга → доступный слот с часовым поясом → вход → проверка контакта и правил → оплата при необходимости → подтверждённая запись → «Моё» → напоминание → ссылка онлайн или адрес офлайн → посещение → обратная связь / повторная запись.

Ветви: нет слотов → лист ожидания / другой мастер; слот занят во время оформления → выбор нового времени с сохранением услуги; запрос индивидуального времени → отдельная заявка без обещания подтверждения. Реальные отзывы публикуются после проверки, демонстрационные отзывы не выдаются за реальные.

## 4. Групповое занятие онлайн / офлайн

Календарь → формат → дата → занятие → программа, мастер, уровень, длительность, места, цена, правила отмены → «Записаться» → резерв места → оформление → оплата / бесплатное подтверждение → билет и запись в «Моё».

Онлайн: часовой пояс → рабочая ссылка, доступная участнику в нужное время → информация о записи вебинара, если она предусмотрена. Офлайн: город → точный адрес → карта / маршрут → что взять с собой.

Если мест нет: «Встать в лист ожидания» → уведомление с ограниченным сроком предложения места. Перенос организатором: сообщение → новое время → согласиться или запросить возврат по условиям. Отмена пользователем: запись → правила и ожидаемая сумма → подтверждение отмены → статус возврата. Не удалять билет молча.

## 5. Курс и инфопродукт

Материал канала / каталог → страница курса → кому подходит, результат без завышенных обещаний, программа, автор, формат, срок доступа, цена → бесплатный фрагмент → «Купить курс» → вход → выбор допустимого способа оплаты для поверхности и товара → подтверждение сервером → право доступа → первый урок → прогресс → возврат через «Моё».

Платёж: успех → доступ; отмена → вернуться к оформлению; отказ → другой допустимый способ / повтор; неизвестный результат → «Проверяем оплату» без повторного списания; деньги списаны, доступа нет → восстановить покупку / помощь с номером заказа. Одна покупка сохраняется при переключении YOG / SATTVA.

## 6. YOG: событие под ключ

Соцсеть / общая главная → YOG → «Собрать событие» → частное / корпоративное / PR → формат или релевантный кейс → короткий бриф: повод, город, дата или диапазон, количество участников, бюджет или «нужен ориентир», пожелания → контакт и согласие → отправить → номер заявки и следующий шаг → уточнение менеджером → предложение → согласование состава, даты и цены → договор и оплата по согласованному процессу → подготовка → событие → обратная связь.

Нет даты / бюджета → можно отправить запрос с ориентиром. Черновик сохраняется при возврате назад. Отправка брифа не означает бронирование даты или мгновенный расчёт. Срок ответа показывается только если команда реально может его выполнять.

Открытое событие YOG: афиша → детали → билет → стандартное оформление → «Моё». Не заставлять покупателя билета заполнять корпоративный бриф.

## 7. Переход между направлениями

SATTVA → контекстная рекомендация «Создать такую встречу для близких» → YOG / релевантный формат → бриф. YOG → после события «Продолжить заботу о себе» → SATTVA / подходящая практика. Переход добровольный; автоматического переключения во время покупки нет.

## 8. Telegram → единая библиотека

Пост с прямой ссылкой → конкретный материал / занятие → при необходимости вход → возврат на исходную страницу → действие → сохранение в «Моё». Материал внутри приложения показывает рубрику и источник. Редакционная лента позволяет найти прошлые публикации по теме, а не только по дате.

## 9. Автор: свой мини-курс

«Стать автором» → заявка и подтверждение профиля → черновик курса → программа и уроки → загрузка файлов → цена, условия доступа и права → предпросмотр → отправка на модерацию → правки или публикация → продажи → управление доступом и запросами. Ученик не видит незавершённый черновик; выплаты и комиссии раскрываются до публикации.

## 10. Профиль, поддержка и восстановление

«Моё» → записи / покупки / избранное / заявки → конкретный объект → следующее действие. Настройки → часовой пояс, уведомления, связанные аккаунты, приватность и удаление. Помощь доступна из заказа с его номером без запроса повторно описывать всю ситуацию.

## Границы интерактивного прототипа

Нужно кликабельно пройти: SATTVA → подбор → практика → демоплеер; мастер → услуга → слот → демоподтверждение; календарь → онлайн/офлайн → запись; курс → демонстрационная покупка → урок; YOG → бриф → статус заявки; канал → материал → избранное; «Моё» → сохранённые результаты. Переключение направлений, возврат, фильтры, ошибки формы и пустые состояния должны работать. Платежи, авторизация, отправка сообщений, реальные бронирования и синхронизация Telegram обозначаются как симуляция. Демо не должно молча имитировать реальную отправку заявки.
