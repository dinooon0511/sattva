# YOG / SATTVA · интерактивное пространство, версия 2

Одна страница для проверки большой продуктовой системы: кликабельный прототип Telegram Mini App, JTBD, CJM, User Flow, концепция, аудит и бизнес-модель.

**SATTVA** — все личные практики, медитации, видеоуроки, курсы, преподаватели и онлайн-/офлайн-занятия. **YOG** — коммерческая организация дней рождения, девичников, корпоративных и PR-событий под ключ. Профиль, история покупок и заявки общие; каталоги не дублируются между направлениями.

## Содержимое демонстрации

- 24 материала: несколько медитаций, йога, дыхание, подкасты и вебинары; фильтры аудио/видео, поиск и подбор.
- 8 программ: онлайн и офлайн; в том числе 4 дня в Санкт-Петербурге с Марией и 2 дня в Москве. У курса есть программа, включения/исключения, условия и закреплённая цена.
- 6 преподавателей: фильтры, подход, пример квалификации, знакомство, личное занятие и пакет.
- 12 групповых занятий: формат, город, дата, отмена с подтверждением, лист ожидания.
- 6 коммерческих форматов YOG: состав, ориентир бюджета, отдельные расходы, адаптивный бриф и путь заявки.
- Недельный маршрут, демоклуб, подарок, настройки напоминаний.
- Кабинет преподавателя: черновик программы, демонстрационные слоты, модель дохода.
- 15 JTBD, 7 CJM, 13 User Flow; экспертный аудит, воронки и изменяемая экономика по четырём моделям.

## Границы

Это демонстрация без реальных платежей, бронирований, сообщений, медиауроков, загрузки файлов и выплат. Плееры используют текстовые шаги и явно подписаны как макеты без звука и видеопотока. Все профили, даты, цены, квалификация и доступность вымышлены. Данные хранятся в localStorage этого браузера; межустройственной синхронизации нет. До рабочих продаж требуются серверные заказы, проверка платежей, права доступа, резервы, роли, реальные авторы/медиа/расписание, оферты, возвраты и поддержка.

## Разработка

Node.js 24, npm 11. Используйте существующий checkout — задача уже изолирована.

```sh
npm ci --cache /tmp/sattva-npm-cache --no-audit --no-fund
npm run dev -- --host 0.0.0.0 --port 4173 --strictPort
npm test
```

```sh
npm run build
node scripts/verify-dist.mjs
npm run preview -- --host 0.0.0.0 --port 4174 --strictPort
TEST_URL=http://127.0.0.1:4174 npm test
```

Браузерные проверки используют `/usr/bin/chromium`; `CHROMIUM_PATH` позволяет задать другой executable. Скриншоты и автономный экспорт находятся в игнорируемой `artifacts/`. Текущие исходные свидетельства аудита — в `public/audit/` и доступны внутри раздела «Аудит».

```sh
node scripts/export-standalone.mjs
```

Создаёт `artifacts/sattva-prototype.html` с встроенными кодом, стилями и изображениями. Файл не заменяет проверку публикации.

## Публикация

GitHub Pages, репозиторий `dinooon0511/sattva`. Workflow `.github/workflows/pages.yml` собирает приложение, проверяет production HTML и публикует `dist`. В Pages должна использоваться публикация через GitHub Actions. Статус `built` и HTTP 200 не доказывают загрузку приложения: нужно проверить, что HTML ссылается на собранные `assets`, все ресурсы загружаются, интерфейс рендерится и ключевые клики работают на публичном адресе.

## Структура

`src/Prototype.jsx` — пользовательские сценарии; `src/product.js` — каталог и форматы; `src/strategy.js` — расширенные карты и аудит; `src/BusinessViews.jsx` — аудит, воронки, калькулятор и дорожная карта; `src/main.jsx` — оболочка и аналитические карты; `docs/01–07` — полные документы. `design-qa.md` фиксирует последнюю визуальную и функциональную проверку.

### Проверка публичной страницы

```sh
node tests/live.mjs
```

Пять репрезентативных сценариев на опубликованном адресе. В управляемой среде тест использует доверенный CA Node и унаследованный прокси для HTTPS-запросов, затем передаёт проверенные ответы Chromium; проверка TLS не отключается. Итог проверки текущей публикации записан в `design-qa.md`.
